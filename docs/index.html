Compile a JX page declaration into a native Windows window executable.

JX can read PHP input containing jx_* page declarations, emit a GCC-compilable C file, and build that file into a native Win32 executable. The result opens its own native window, renders with Win32/GDI, and exposes a small localhost API for live state updates.

1. Overview

The native window C emission workflow turns a small PHP declaration file into a generated C program, then into a Windows executable. The PHP file is used as a declarative input surface: title, badge, body, modal content, iframe content, JSON attachment data, and local API enablement are captured by JX and written into generated C.

1PHP inputin.php contains jx_* declarations.
2JX emitjx -o out.c in.php generates C.
3GCC buildCompile with Win32 libraries.
4Native EXERun a Win32/GDI window.
5Local APIQuery and update via localhost routes.
The important promise is simple: this is not a browser wrapper. The generated program owns a native Windows window and links directly against Windows libraries.

2. Requirements

JX native executable

Build JX from the native C source before using the emission flow.

gcc -O2 -Wall -Wextra -o jx src/native/jx.c
GCC or MinGW-w64

Use GCC on Windows/MSYS2 or a MinGW-w64 cross compiler on Linux/WSL.

C:\msys64\ucrt64\bin\gcc.exe
Windows libraries

The generated C executable links against Winsock and Win32/GDI libraries.

-lws2_32 -lgdi32 -luser32
  • JX: built from src/native/jx.c
  • Windows/MSYS2 compiler: C:\msys64\ucrt64\bin\gcc.exe
  • Linux/WSL compiler: x86_64-w64-mingw32-gcc
  • Required Windows libraries: ws2_32, gdi32, user32

3. Basic Workflow

Start with a PHP declaration file and ask JX to emit C. The -o argument names the generated C file. 

jx -o out.c in.php

After emission, JX prints the follow-up GCC command to compile the generated C file. Use that command as the authoritative next step for the current generated output.

4. Compile Command

The normal native window compile command is:

gcc -O2 -Wall -Wextra -mwindows -I . -o out.exe out.c -lws2_32 -lgdi32 -luser32
Library order matters with GCC/MinGW. Put the libraries after out.c. In particular, -lws2_32 must appear after the generated C input so Winsock references such as socket and WSAStartup resolve correctly.

5. PowerShell Example

Use this from Windows PowerShell when MSYS2 UCRT64 is installed at C:\msys64.

$gcc = "C:\msys64\ucrt64\bin\gcc.exe"

& $gcc -O2 -Wall -Wextra -o jx.exe src/native/jx.c

.\jx.exe -o out.c examples\native_window_input.php

& $gcc -O2 -Wall -Wextra -mwindows -I . -o out.exe out.c -lws2_32 -lgdi32 -luser32

.\out.exe

If jx.exe is already built and on PATH, the middle steps can be shortened:

jx -o out.c examples\native_window_input.php
C:\msys64\ucrt64\bin\gcc.exe -O2 -Wall -Wextra -mwindows -I . -o out.exe out.c -lws2_32 -lgdi32 -luser32
.\out.exe

6. Linux / WSL Cross-Compile Example

Install MinGW-w64, build or use JX, emit C, and cross-compile a Windows executable.

sudo apt-get update
sudo apt-get install -y gcc mingw-w64 curl

gcc -O2 -Wall -Wextra -o jx src/native/jx.c

./jx -o out.c examples/native_window_input.php

x86_64-w64-mingw32-gcc -O2 -Wall -Wextra -mwindows -I . -o out.exe out.c -lws2_32 -lgdi32 -luser32

The resulting out.exe is a Windows executable. Copy it to Windows or run it through a compatible environment.

7. jx_* Page Declarations

JX recognizes the following declaration names in the input PHP file. These declarations describe the native window page and data that should be embedded into generated C.

DeclarationPurpose
jx_page_titleSets the native window/page title.
jx_page_badgeSets a short badge or status label rendered by the page.
jx_page_bodySets the main body content for the window.
jx_modal_titleSets the modal title text compiled into the executable.
jx_modal_bodySets the modal body text compiled into the executable.
jx_iframe_titleSets the title for iframe-style embedded content.
jx_iframe_htmlSets HTML-like content for the iframe/island payload.
jx_page_jsonEmbeds attachment JSON returned by the local /json endpoint.
jx_local_apiEnables the localhost API in the native executable.

8. Local API

When jx_local_api is enabled, the native executable starts a localhost API server for inspection and lightweight updates. These routes are intended for local development and native-window state wiring.

RouteBehavior
/jsonReturns the compiled attachment JSON from jx_page_json.
/update?title=...&badge=...&body=...Updates page title, badge, and body fields.
/modal?title=...&body=...Updates modal title and modal body fields.
/iframe?title=...&html=...Updates iframe title and iframe HTML payload.
 
curl http://127.0.0.1:8787/json
curl "http://127.0.0.1:8787/update?title=Hello&badge=Live&body=Updated"
curl "http://127.0.0.1:8787/modal?title=Notice&body=Modal%20body"
curl "http://127.0.0.1:8787/iframe?title=Frame&html=%3Ch1%3EHi%3C%2Fh1%3E"

9. Example Input

Use examples/native_window_input.php as the main native window example. A compact annotated version looks like this: 

<?php
// Window title rendered by the native executable.
jx_page_title("JX Native Window");

// Small status badge in the page header.
jx_page_badge("native");

// Main visible page copy.
jx_page_body("This PHP declaration file emits C for a Win32/GDI window.");

// Modal payload compiled into the executable.
jx_modal_title("Compiled Modal");
jx_modal_body("This modal text came from the PHP input file.");

// Iframe/island payload.
jx_iframe_title("Embedded Island");
jx_iframe_html("<h1>JX Island</h1><p>No browser dependency.</p>");

// Attachment JSON returned by /json.
jx_page_json('{"engine":"jx","target":"native-window-c"}');

// Enable localhost routes such as /json and /update.
jx_local_api(true);

10. CSS

When a sibling style.css file exists next to the PHP input, JX infers it and embeds it into the generated C. This lets a page keep its text declarations in PHP and its style rules beside it. 

examples/native_window_input.php
examples/style.css

Then emit and compile as usual: 

jx -o out.c examples/native_window_input.php
gcc -O2 -Wall -Wextra -mwindows -I . -o out.exe out.c -lws2_32 -lgdi32 -luser32

11. Includes, Requires, CSS Images

Bridge-mode bundling follows static quoted relative paths for PHP include-style statements. The supported statement forms are:

  • include
  • include_once
  • require
  • require_once

Static relative includes can be folded into the emitted output, allowing multi-file declaration pages to produce a single generated C file and then a single native executable. 

<?php
require_once "partials/header.php";
include "partials/body.php";

jx_page_title("Bundled JX Page");

CSS asset bundling also handles quoted or url(...) image references when they are static relative paths. Use examples/single_exe_page/page.php as the reference shape for a single-executable page with CSS and image assets bundled into the generated C. 

examples/single_exe_page/page.php
examples/single_exe_page/style.css
examples/single_exe_page/assets/logo.png
.hero {
  background-image: url("assets/logo.png");
}

12. Troubleshooting

Winsock linker errors

A common failed compile looks like this:

undefined reference to __imp_socket
undefined reference to __imp_WSAStartup

This means -lws2_32 is missing or appears before out.c. Fix the command by putting all Windows libraries after the generated C file: 

gcc -O2 -Wall -Wextra -mwindows -I . -o out.exe out.c -lws2_32 -lgdi32 -luser32

13. What This Is Not

  • It is not a WebView wrapper.
  • It is not opening Chrome, Edge, Firefox, or a system browser.
  • It is a native Win32/GDI window renderer.
  • PHP runtime bridging is separate from native jx_* page emission.

The native page emission path is a compile-time declaration workflow. Arbitrary PHP/Zend runtime behavior, Oracle mirroring, and broader PHP compatibility are separate JX architecture layers.
